# Watch S4 2048 · 1.1.0

从用户提供的 `com.sapnapboy.watch2048.debug.1.0.0.rpk` 还原可维护源码，使用同版官方 aiot-toolkit 2.0.5 构建。

## 使用

安装 `com.sapnapboy.watch2048.debug.1.1.0.rpk`。包名不变，版本号为 1.1.0 / 2。
优先覆盖安装；不要为了升级先卸载旧版，否则可能丢失存档。保留原来的 `game-v1` 存档键和棋盘、分数字段，新增设置字段可兼容读取旧存档。

- 点顶部“连合：关/开”，启用或关闭同方向连续合并。首次安装与旧存档迁移默认关闭。
- 开启后，一次滑动会依同方向进行多轮标准合并，直到不能继续，最后只生成一个新方块。例如 `16,8,8 → 16,16 → 32`，得分增加 `16+32=48`。
- 关闭后，保持标准 2048 一次滑动每块最多合并一次。
- 点“动画：开/关”可关闭动画，降低额外绘制负担。默认开启轻量动画。
- 点底部“新局”重置棋盘，保留两个设置。

## 动画与负载控制

- 基础滑动：每个合并阶段 3 次位置更新，约 100ms；最终新增/合并格用约 80ms 的明暗反馈。
- 不使用常驻刷新、setInterval、无限动画或逐帧全棋盘重建。
- 固定复用 16 个方块和 16 个底格；仅修改方块的显示字段。
- 4×4 棋盘最多 3 个合并阶段，不采用无界循环。整轮最多 10 个串行定时回调，同时至多 1 个。
- 动画期间锁定输入；手势结束即消费，过滤短滑、近对角线、多点与错位手指。关闭动画时也保留 160ms 输入间隔。
- 页面隐藏/销毁时取消定时器并结算为最终棋盘；先保存整轮最终状态，避免中间动画状态入档。
- 存储写入串行化，合并等待中的最新存档，避免异步旧写入覆盖新局面。

这些措施控制应用额外负担，不能保证真机不会触发温控或系统重启。模拟器不能验证真实芯片功耗、温度与固件温控策略。

## 构建与测试

需要 Node.js 与 npm。示例验证环境：Node 24、Linux x86_64。

```sh
npm ci
npm test
npm run build
```

产物在 `dist/`。这是 debug RPK，沿用官方工具链的调试签名方式，不包含用户的发行私钥。

主要代码：

- `src/common/game.js`：纯逻辑、单轮移动与有界连续合并规划。
- `src/common/gesture.js`：手势判断。
- `src/pages/index/page.js`：页面、轻量动画、设置及存档。
- `src/pages/index/index.ux`：界面与颜色。
- `test/`：合并、计分、随机生成、2500 组方向/棋盘枚举、手势、生命周期和存储并发测试。
